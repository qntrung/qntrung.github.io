Lộ trình làm chủ Claude cho lập trình viên

Fri 30 October 2026
By TrungQuach

Lộ trình 6 session (khoảng 3 tuần, mỗi tuần 2 session, mỗi session 3–4 giờ) dành cho lập trình viên đã quen trò chuyện với Claude trên claude.ai và muốn đi sâu vào phần dành cho dev: Claude Code, MCP, Claude API và Agent.

Mỗi session được chia thành:

  • Các Step bài học: giải thích ngắn, ví dụ mẫu chép và chạy được, kèm một việc nhỏ để “thử ngay”.
  • Bài tập: có bối cảnh, các bước làm và kết quả mong đợi. Phần gợi ý được ẩn, chỉ mở khi bị kẹt.
  • Đề án cuối session: đặc tả, các mốc (milestone) kèm prompt mẫu, và checklist nghiệm thu.

Xuyên suốt lộ trình là một dự án chạy dần: expense-cli, công cụ quản lý chi tiêu viết bằng Python. Session 1 xây nó, Session 2 tự động hoá repo, Session 3 viết MCP server cho nó, Session 4–5 xây chatbot và agent quanh nó, Session 6 đưa mọi thứ vào thực tế.

Chuẩn bị

  • Gói Claude Pro hoặc Max (để dùng Claude Code), hoặc API key trên Claude Console.
  • Một API key cùng ít credit cho Session 4–6. Đặt hạn mức chi tiêu (spend limit) trong Console ngay từ đầu.
  • Python 3.12+ với uv, Node.js 18+, Git, GitHub CLI (gh), Docker (cho Session 5), cùng VS Code hoặc JetBrains.
  • Một repo GitHub trống tên expense-cli.

Session 1: Claude Code cơ bản

Tuần 1 · ~4 giờ học + 3–5 giờ đề án · Công cụ: Claude Code, Git, GitHub

Mục tiêu: để Claude làm việc trực tiếp trong codebase của bạn (đọc file, sửa code, chạy lệnh, chạy test, commit) và biết cách điều khiển nó.

Đầu ra: Claude Code chạy được trên máy, một file CLAUDE.md tốt, và ứng dụng expense-cli hoàn chỉnh có test.

▶ Thử ngay: cd vào một dự án bất kỳ, gõ claude, rồi hỏi: “Thư mục này là dự án gì? Tóm tắt trong 5 dòng, kèm cách chạy nó.”

Step 3 CLAUDE.md: bộ nhớ của dự án

Claude đọc CLAUDE.md ở đầu mỗi phiên. Đây là nơi ghi những gì một đồng nghiệp mới cần biết: lệnh build/test, kiến trúc, quy ước, những điều cấm. Chạy /init để Claude tự tạo bản nháp, sau đó bạn đọc và sửa lại.

Ví dụ mẫu (sẽ dùng cho expense-cli):

markdown# expense-cli

CLI quản lý chi tiêu cá nhân. Python 3.12, Typer, SQLite.

## Lệnh thường dùng
- Cài đặt: `uv sync`
- Chạy test: `uv run pytest -q`
- Lint + format: `uv run ruff check . --fix && uv run ruff format .`
- Chạy app: `uv run expense --help`

## Kiến trúc
- `src/expense/cli.py`    – định nghĩa lệnh (Typer), KHÔNG chứa SQL
- `src/expense/db.py`     – truy cập SQLite, nơi duy nhất được viết SQL
- `src/expense/models.py` – dataclass nghiệp vụ
- `migrations/`           – file SQL đánh số 0001_, 0002_, ...

## Quy ước
- Type hint đầy đủ; hàm public có docstring
- Tiền lưu dạng số nguyên (đồng). KHÔNG dùng float cho tiền
- Mỗi tính năng mới phải có test trong `tests/`
- Commit theo Conventional Commits (feat:, fix:, chore:, ...)

## Không được làm
- Không sửa migration đã commit, hãy tạo migration mới
- Không commit file `*.db` hoặc `.env`
  • Vị trí: ./CLAUDE.md (commit, cả nhóm dùng chung), ~/.claude/CLAUDE.md (cá nhân, áp dụng cho mọi dự án), hoặc CLAUDE.md trong thư mục con (được nạp khi Claude làm việc ở đó).
  • Có thể import file khác: viết @docs/architecture.md bên trong CLAUDE.md.
  • Dùng /memory để mở và sửa nhanh.
  • Giữ ngắn gọn. Mỗi dòng phải có lý do tồn tại. Khi thấy Claude lặp lại cùng một lỗi, hãy thêm một dòng quy tắc.

▶ Thử ngay: Chạy /init trên dự án của bạn. Gạch bỏ những dòng chung chung (“viết code sạch”) và thêm 3 quy tắc thật sự riêng của dự án.

Bài tập Session 1

Bài 1.1: Khám phá một codebase lạ

Bối cảnh: bạn vừa vào một dự án mới, cần hiểu codebase thật nhanh.

  1. git clone https://github.com/pallets/click && cd click && claude
  2. Hỏi lần lượt: “Khi chạy một lệnh Click, code đi qua những class/hàm nào từ lúc gọi đến lúc thực thi callback?”, “Option được parse ở đâu?”, “Muốn thêm một kiểu tham số mới thì sửa ở đâu?”

  4. Tự mở 2–3 file trong sơ đồ để kiểm chứng.

Kết quả mong đợi: trong 30 phút, bạn giải thích được luồng xử lý cho người khác mà không cần nhìn ghi chú.

Bài 1.2: CLAUDE.md trước và sau
  1. Trên dự án của bạn, tạm đổi tên CLAUDE.md (nếu có). Yêu cầu Claude thêm một tính năng nhỏ. Ghi lại: nó có chạy đúng lệnh test không, có theo đúng convention không?
  2. /init, sửa CLAUDE.md theo mẫu ở Step 3, rồi /clear.

  4. So sánh hai lần theo các tiêu chí: số lần bạn phải sửa hướng, có chạy test không, có đúng convention không.
Bài 1.3: Sửa bug theo TDD

Tạo file bill.py có bug sau:

pythondef split_bill(total: int, people: int) -> list[int]:

Gợi ý lời giải 
pythondef split_bill(total: int, people: int) -> list[int]:
    if people <= 0:
        raise ValueError("people must be positive")
    share, remainder = divmod(total, people)
    return [share + 1] * remainder + [share] * (people - remainder)

Các mốc thực hiện (kèm prompt mẫu)
  1. M0 · Khởi tạo: “Khởi tạo dự án Python 3.12 bằng uv, src layout, package expense, dùng Typer, pytest, pytest-cov, ruff. Thêm lệnh expense --version và 1 test. Chưa làm tính năng.” Sau đó chạy /init rồi chỉnh CLAUDE.md theo mẫu ở Step 3.
  2. M1 · Lớp DB và migration (plan mode): “Lập kế hoạch cho db.py: kết nối SQLite (đường dẫn lấy từ biến môi trường EXPENSE_DB, mặc định ~/.expense.db), hệ thống migration đơn giản đọc file trong migrations/ và lưu version vào bảng schema_version. Test dùng DB tạm.”
  3. M2 · add / list / delete: viết test trước cho các trường hợp: số tiền âm, ngày sai định dạng, danh mục rỗng, lọc theo tháng.
  4. M3 · report: format tiền kiểu Việt Nam (dấu chấm ngăn cách hàng nghìn), dùng rich để vẽ bảng.
  5. M4 · import / export: “Import CSV gồm các cột date, amount, category, note. Dòng lỗi thì bỏ qua và báo số dòng cùng lý do, không được dừng cả quá trình. Thêm file mẫu tests/fixtures/sample.csv có cả dòng lỗi.”
  6. M5 · Chất lượng: “Chạy coverage, bổ sung test tới khi đạt ≥ 80%. Sửa mọi cảnh báo ruff. Viết README: cài đặt, ví dụ dùng, cách phát triển.”
  7. M6 · Phát hành: mỗi mốc là một PR có mô tả rõ ràng, merge vào main, gắn tag v0.1.0.
Checklist nghiệm thu

2. Tìm code liên quan. Tóm tắt nguyên nhân gốc trong tối đa 3 câu.

7. Báo cáo: nguyên nhân, cách sửa, các file đã đổi.

Step 4 Hooks: quy tắc chạy chắc chắn, không phụ thuộc vào việc Claude có nhớ hay không

CLAUDE.md chỉ là lời khuyên. Hook là luật: một lệnh shell chạy tự động tại các thời điểm như PreToolUse (trước khi dùng công cụ), PostToolUse (sau khi dùng), Stop (khi Claude định kết thúc lượt), UserPromptSubmit, SessionStart, Notification… Hook nhận dữ liệu JSON qua stdin. Nếu hook exit code 2, hành động bị chặn và nội dung stderr được gửi lại cho Claude.

Thêm vào .claude/settings.json:

json{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | grep '\\.py$' | xargs -r uv run ruff format"
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/block-dangerous.sh" }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/require-green-tests.sh" }
        ]
      }
    ]
  }
}
bash#!/usr/bin/env bash
# .claude/hooks/block-dangerous.sh – chặn lệnh nguy hiểm
cmd=$(jq -r '.tool_input.command')
if echo "$cmd" | grep -Eq 'rm -rf|git push (-f|--force)|DROP TABLE|git reset --hard'; then
  echo "Lệnh bị chặn bởi hook bảo vệ: $cmd. Hãy tìm cách khác an toàn hơn." >&2
  exit 2
fi
exit 0
bash#!/usr/bin/env bash
# .claude/hooks/require-green-tests.sh – không cho kết thúc lượt khi test còn đỏ
input=$(cat)
# Tránh vòng lặp vô hạn: nếu đã bị hook chặn một lần thì cho qua
if [ "$(echo "$input" | jq -r '.stop_hook_active')" = "true" ]; then exit 0; fi
if ! uv run pytest -q > /tmp/expense-pytest.log 2>&1; then
  echo "Test đang FAIL. Hãy sửa trước khi kết thúc:" >&2
  tail -30 /tmp/expense-pytest.log >&2
  exit 2
fi
exit 0

Step 1 MCP là gì

MCP là chuẩn mở giúp ứng dụng AI (MCP client, như Claude Code hay Claude Desktop) kết nối với công cụ và dữ liệu bên ngoài thông qua MCP server.

text Claude Code / Claude Desktop  (MCP client)
            │   JSON-RPC qua stdio (local) hoặc HTTP (từ xa)
            ▼
       MCP server ───────►  SQLite / REST API / file / trình duyệt

       ├─ resources  dữ liệu để đọc:        expenses://categories
       └─ prompts    mẫu prompt có sẵn:     /monthly_review

So với tự viết tool trong từng ứng dụng, MCP giúp viết một lần, dùng ở mọi client.

pythonimport os
import sqlite3
from datetime import date

from mcp.server.fastmcp import FastMCP

DB_PATH = os.environ.get("EXPENSE_DB", os.path.expanduser("~/.expense.db"))
mcp = FastMCP("expenses")


def _conn() -> sqlite3.Connection:
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    return conn


@mcp.tool()
def list_expenses(month: str, category: str | None = None) -> list[dict]:
    """Liệt kê các khoản chi trong một tháng.

    Args:
        month: Tháng dạng YYYY-MM, ví dụ 2026-11.
        category: Lọc theo danh mục (an-uong, di-chuyen, ...). Bỏ trống để lấy tất cả.
    """
    sql = "SELECT id, amount, category, note, spent_on FROM expenses WHERE strftime('%Y-%m', spent_on) = ?"
    params: list = [month]
    if category:
        sql += " AND category = ?"
        params.append(category)
    with _conn() as conn:
        return [dict(r) for r in conn.execute(sql + " ORDER BY spent_on", params)]


@mcp.tool()
def monthly_total(month: str) -> dict:
    """Tổng chi theo từng danh mục trong tháng (YYYY-MM). Số tiền tính bằng đồng."""
    with _conn() as conn:
        rows = conn.execute(
            "SELECT category, SUM(amount) AS total FROM expenses "
            "WHERE strftime('%Y-%m', spent_on) = ? GROUP BY category ORDER BY total DESC",
            (month,),
        ).fetchall()
    by_cat = {r["category"]: r["total"] for r in rows}
    return {"month": month, "by_category": by_cat, "total": sum(by_cat.values())}


@mcp.tool()
def add_expense(amount: int, category: str, note: str = "", spent_on: str | None = None) -> str:
    """Thêm một khoản chi mới.

    Args:
        amount: Số tiền (đồng), số nguyên dương. Ví dụ 50000.
        category: Danh mục, viết thường, nối bằng gạch ngang. Ví dụ an-uong.
        note: Ghi chú ngắn.
        spent_on: Ngày chi dạng YYYY-MM-DD. Bỏ trống = hôm nay.
    """
    if amount <= 0:
        raise ValueError("amount phải là số nguyên dương")
    day = spent_on or date.today().isoformat()
    date.fromisoformat(day)  # raise nếu sai định dạng
    with _conn() as conn:
        cur = conn.execute(
            "INSERT INTO expenses (amount, category, note, spent_on) VALUES (?, ?, ?, ?)",
            (amount, category, note, day),
        )
    return f"Đã thêm #{cur.lastrowid}: {amount:,}đ · {category} · {day}".replace(",", ".")


@mcp.resource("expenses://categories")
def categories() -> str:
    """Danh sách danh mục đang dùng, kèm số khoản chi."""
    with _conn() as conn:
        rows = conn.execute("SELECT category, COUNT(*) AS n FROM expenses GROUP BY category").fetchall()
    return "\n".join(f"{r['category']}: {r['n']} khoản" for r in rows)

import json, subprocess
from pathlib import Path
import anthropic
from dotenv import load_dotenv

load_dotenv()
client = anthropic.Anthropic()
ROOT = Path(".").resolve()
MAX_STEPS = 15

def safe(path: str) -> Path:
    p = (ROOT / path).resolve()
    if not p.is_relative_to(ROOT):
        raise ValueError("Không được truy cập ngoài thư mục dự án")
    return p

def list_dir(path: str = ".") -> str:
    return "\n".join(sorted(x.name + ("/" if x.is_dir() else "") for x in safe(path).iterdir()))

def read_file(path: str) -> str:
    return safe(path).read_text()[:20_000]

def run_tests(target: str = "") -> str:
    r = subprocess.run(["uv", "run", "pytest", "-q", "-x", target] if target else ["uv", "run", "pytest", "-q", "-x"],
                       capture_output=True, text=True, timeout=300, cwd=ROOT)
    return (r.stdout + r.stderr)[-6000:]

TOOLS = [
    {"name": "list_dir", "description": "Liệt kê file trong thư mục (đường dẫn tương đối).",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}}}},
    {"name": "read_file", "description": "Đọc nội dung một file (đường dẫn tương đối).",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}}, "required": ["path"]}},
    {"name": "run_tests", "description": "Chạy pytest. target có thể là file hoặc test cụ thể, bỏ trống để chạy tất cả.",
     "input_schema": {"type": "object", "properties": {"target": {"type": "string"}}}},
]
HANDLERS = {"list_dir": list_dir, "read_file": read_file, "run_tests": run_tests}

def run(task: str) -> str:
    messages = [{"role": "user", "content": task}]
    for step in range(1, MAX_STEPS + 1):
        resp = client.messages.create(
            model="claude-opus-5-5", max_tokens=8000, tools=TOOLS, messages=messages,
            system="Bạn là kỹ sư debug. Điều tra có phương pháp, dựa trên bằng chứng. Không đoán.",
        )
        messages.append({"role": "assistant", "content": resp.content})
        if resp.stop_reason != "tool_use":
            return "".join(b.text for b in resp.content if b.type == "text")
        results = []
        for b in resp.content:
            if b.type != "tool_use":
                continue
            print(f"[{step}] {b.name}({json.dumps(b.input, ensure_ascii=False)})")
            try:
                out, err = HANDLERS[b.name](**b.input), False
            except Exception as e:
                out, err = f"Lỗi: {e}", True
            results.append({"type": "tool_result", "tool_use_id": b.id, "content": out, "is_error": err})
        messages.append({"role": "user", "content": results})
    return "Dừng: vượt quá số bước cho phép."

if __name__ == "__main__":

Mỗi subagent có context riêng, nên agent chính chỉ nhận bản tóm tắt kết quả. Nhờ vậy context của agent chính không bị đầy khi làm việc lớn.

Step 7 Evals: đo xem agent tốt đến đâu

Không có eval thì mọi thay đổi prompt chỉ là đoán mò. Một bộ eval tối thiểu gồm: bộ dữ liệu, cách chấm điểm, và script chạy lặp lại được.

python# eval_agent.py
import json, asyncio
from pydantic import BaseModel

class Grade(BaseModel):
    found_bug: bool
    false_positives: int
    reasoning: str

def judge(expected_bug: str, review_text: str) -> Grade:
    return client.messages.parse(
        model="claude-opus-5-5", max_tokens=2000, output_format=Grade,
        messages=[{"role": "user", "content":
            f"<bug_that_exists>{expected_bug}</bug_that_exists>\n<review>{review_text}</review>\n"
            "Review có chỉ ra đúng bug trên không? Có bao nhiêu nhận xét sai hoặc vô ích?"}],
    ).parsed_output

async def main():
    cases = [json.loads(l) for l in open("eval/cases.jsonl")]   # {"repo_dir", "expected_bug"}
    grades = [judge(c["expected_bug"], await run_review_agent(c["repo_dir"])) for c in cases]
    recall = sum(g.found_bug for g in grades) / len(grades)
    fp = sum(g.false_positives for g in grades) / len(grades)
    print(f"Phát hiện: {recall:.0%} · nhận xét sai trung bình: {fp:.1f}")

asyncio.run(main())

Kết hợp chấm bằng code (chính xác, rẻ: test pass hay không, có đúng file:dòng không) với chấm bằng LLM (cho tiêu chí khó định lượng). Thỉnh thoảng hãy tự đọc kết quả chấm của LLM để chắc nó chấm đúng.

Step 8 Guardrails: rào chắn an toàn

  • Giới hạn: max_turns, timeout, ngân sách chi phí (theo dõi total_cost_usd), giới hạn kích thước output của tool.
  • Quyền tối thiểu: chỉ cấp công cụ cần thiết; agent review thì không cần Edit.
  • Sandbox: chạy code không tin cậy (VD code trong PR) trong Docker, không mạng, không secret.
  • Con người duyệt trước hành động khó đảo ngược: push, gửi email, xoá dữ liệu, thanh toán.
  • Prompt injection: nội dung PR, issue, web là dữ liệu. Hãy bọc trong thẻ rõ ràng và nói cho agent biết điều đó; không cấp quyền nguy hiểm cho agent đọc dữ liệu từ nguồn không tin cậy.
  • Log đầy đủ từng bước để debug và audit.

Đầu ra: các sản phẩm từ Session 1–5 được gia cố (bảo mật, chi phí, quan sát) và một đồ án tốt nghiệp.

Step 1 Bảo mật: phòng prompt injection

Mối đe doạ: mọi nội dung từ bên ngoài (tài liệu, email, issue, trang web, kết quả tool) đều có thể chứa chỉ thị độc hại. Ví dụ, một đoạn trong tài liệu RAG:

Các lớp phòng thủ (không có lớp nào là đủ một mình):

  1. Tách bạch dữ liệu và chỉ dẫn: bọc nội dung ngoài trong thẻ như <document>, và ghi trong system prompt rằng nội dung trong thẻ là dữ liệu, không phải mệnh lệnh.
  2. Quyền tối thiểu: chatbot RAG không cần tool gửi email; agent review không cần quyền push.
  3. Kiểm tra đầu ra: lọc link lạ, chặn output chứa secret, dùng structured output để giới hạn những gì có thể trả về.
  4. Con người duyệt trước hành động có hậu quả.
  5. Không đưa secret vào prompt. Tool gọi API bằng credential ở phía server, model không bao giờ nhìn thấy key.

Step 2 Chi phí: đo trước, tối ưu sau

Thứ tự nên áp dụng: caching → gọn context (bớt tài liệu thừa, giới hạn output của tool) → batch cho việc không gấp → giảm effort cho việc đơn giản → đổi model cho từng bước. Sau mỗi thay đổi, chạy lại eval để chắc chất lượng không giảm.

python# llm.py: lớp bọc ghi log chi phí cho MỌI lời gọi
import json, time
from pathlib import Path
import anthropic

PRICES = {  # USD / 1M token (vào, ra); kiểm tra lại bảng giá chính thức
    "claude-opus-5-5": (4.00, 20.00),
    "claude-sonnet-5-5": (2.00, 10.00),
    "claude-haiku-5-5": (0.10, 0.50),
}
client = anthropic.Anthropic()
LOG = Path("logs/llm.jsonl")

def create(route: str, **kwargs):
    t0 = time.perf_counter()
    resp = client.messages.create(**kwargs)
    u = resp.usage
    p_in, p_out = PRICES[kwargs["model"]]
    cached = u.cache_read_input_tokens or 0
    written = u.cache_creation_input_tokens or 0
    cost = (u.input_tokens * p_in + written * p_in * 1.25 + cached * p_in * 0.1 + u.output_tokens * p_out) / 1e6
    LOG.parent.mkdir(exist_ok=True)
    with LOG.open("a") as f:
        f.write(json.dumps({
            "ts": time.time(), "route": route, "model": kwargs["model"],
            "in": u.input_tokens, "cache_read": cached, "cache_write": written, "out": u.output_tokens,
            "cost_usd": round(cost, 6), "latency_s": round(time.perf_counter() - t0, 2),
            "stop_reason": resp.stop_reason,
        }) + "\n")
    return resp

▶ Thử ngay: Thay mọi lời gọi trong chatbot Session 4 bằng llm.create(route=...), chạy bộ eval, rồi dùng pandas tổng hợp chi phí theo route.

Step 3 Quan sát (observability)
