Lộ trình làm chủ Claude cho lập trình viên

Fri 30 October 2026
By TrungQuach

Lộ trình 8 session (khoảng 4 tuần, mỗi tuần 2 session, mỗi session 3–4 giờ) dành cho lập trình viên chưa từng dùng Claude. Đi từ chat cơ bản, đến Claude Code, MCP, Claude API, rồi tới tự xây agent. Mỗi session gồm: mục tiêu, kiến thức cần nắm, bài tập thực hành, và một đề án lớn ở cuối để áp dụng mọi thứ vừa học.

Chuẩn bị trước khi bắt đầu

  • Tài khoản claude.ai (gói Pro/Max sẽ dùng được Claude Code; gói Free đủ cho Session 1–2).
  • Tài khoản Claude Console + một ít credit để gọi API (Session 6–8).
  • Node.js 18+, Python 3.10+, Git, một editor (VS Code hoặc JetBrains), tài khoản GitHub.
  • Một repo “sân chơi” riêng (ví dụ claude-playground) để làm bài tập. Đề án các session sau sẽ dùng lại kết quả của session trước.

Session 1 — Làm quen với claude.ai

Thời lượng: ~3 giờ · Công cụ: claude.ai (web/desktop/mobile)

Mục tiêu: dùng thành thạo giao diện chat, biết lúc nào dùng model nào, biết đưa ngữ cảnh (file, ảnh, tài liệu) vào cho Claude, và biết dùng Projects + Artifacts.

Kiến thức cần nắm:

  • Các dòng model: Opus (mạnh nhất, cho việc khó), Sonnet (cân bằng, dùng hằng ngày), Haiku (nhanh, rẻ). Bật/tắt extended thinking cho bài toán cần suy luận.
  • Upload file: code, PDF, ảnh chụp màn hình lỗi, sơ đồ kiến trúc.
  • Projects: gom tài liệu + “custom instructions” dùng chung cho nhiều cuộc hội thoại.
  • Artifacts: Claude tạo trang HTML/React, sơ đồ, tài liệu… xem và chạy trực tiếp.
  • Web search, các connector (Google Drive, GitHub…), tính năng memory, sửa/chạy lại câu hỏi, rẽ nhánh hội thoại.
  • Giới hạn: context window, độ dài hội thoại, Claude có thể sai, luôn kiểm chứng.
Bài 1.1 — Giải thích code lạ. Chọn một file khoảng 200–500 dòng trong dự án bạn đang làm (hoặc một file từ thư viện open-source). Upload và yêu cầu Claude: (a) tóm tắt file làm gì, (b) vẽ luồng gọi hàm bằng sơ đồ Mermaid, (c) chỉ ra 3 điểm có thể là bug. Tự kiểm chứng từng điểm.
Bài 1.2 — Debug từ ảnh chụp. Chụp màn hình một stack trace hoặc lỗi giao diện thật, gửi cho Claude kèm đoạn code liên quan. So sánh câu trả lời khi có và khi không có code đi kèm, rút ra: ngữ cảnh ảnh hưởng thế nào?
Bài 1.3 — So sánh model. Cùng một câu hỏi thiết kế (ví dụ: “thiết kế schema DB cho hệ thống đặt vé xem phim”) hỏi Haiku, Sonnet, Opus, và Opus có bật extended thinking. Ghi lại khác biệt về chất lượng, tốc độ.
Bài 1.4 — Artifact đầu tiên. Yêu cầu Claude tạo một Artifact: trang dashboard nhỏ hiển thị dữ liệu từ file CSV bạn upload (ví dụ log request, chi tiêu cá nhân). Yêu cầu chỉnh 3 lần (màu sắc, thêm bộ lọc, thêm biểu đồ) để làm quen việc lặp.

🎯 Đề án Session 1: “Trợ lý dự án” bằng Projects

Tạo một Project trên claude.ai cho dự án thật bạn đang làm (hoặc một repo open-source bạn quan tâm).

  1. Upload: README, tài liệu kiến trúc, schema DB, coding convention, 3–5 file code quan trọng nhất.
  2. Viết custom instructions cho Project: vai trò của Claude, ngôn ngữ trả lời, chuẩn code của nhóm, định dạng câu trả lời mong muốn.
  3. Dùng Project để làm 3 việc thật: viết tài liệu onboarding cho thành viên mới, sinh test case cho một tính năng, viết mô tả cho một Pull Request.
  4. Xây một file prompts.md gồm ít nhất 10 prompt mẫu bạn thấy hiệu quả (giải thích code, viết test, review, viết commit message…).

Hoàn thành khi: một đồng nghiệp đọc tài liệu onboarding do Claude viết mà không phát hiện sai sót lớn, và bạn có thư viện prompt cá nhân dùng lại được.

Session 2 — Prompt engineering cho lập trình viên

Thời lượng: ~3 giờ · Công cụ: claude.ai

Mục tiêu: viết prompt cho ra kết quả ổn định, đúng ý ngay từ lần đầu; dùng Claude cho review, debug, thiết kế.

Kiến thức cần nắm:

  • Prompt tốt = ngữ cảnh + nhiệm vụ rõ ràng + ràng buộc + định dạng đầu ra. Hãy viết như đang giao việc cho một đồng nghiệp giỏi nhưng mới vào dự án.
  • Dùng thẻ XML để tách phần: <code>, <requirements>, <example>.
  • Few-shot: đưa 1–3 ví dụ mẫu đầu vào/đầu ra.
  • Yêu cầu Claude suy nghĩ từng bước, hoặc bật extended thinking; yêu cầu nêu giả định và hỏi lại khi thiếu thông tin.
  • Chia nhỏ nhiệm vụ lớn (prompt chaining); cho Claude tự kiểm tra lại kết quả.
  • Biết khi nào nên bắt đầu hội thoại mới (context quá dài, hướng đi sai).
Bài 2.1 — Trước & sau. Lấy prompt “viết hàm validate email”. Viết lại thành prompt đầy đủ: ngôn ngữ, phiên bản, chuẩn RFC áp dụng tới đâu, các case phải pass/fail, yêu cầu kèm unit test. So sánh 2 kết quả.
Bài 2.2 — Code review có cấu trúc. Viết một prompt review dùng XML tag, yêu cầu đầu ra là bảng: mức độ (critical/major/minor) — dòng — vấn đề — đề xuất sửa. Chạy trên một diff thật của bạn.
Bài 2.3 — Debug kiểu “rubber duck”. Chọn một bug từng mất nhiều thời gian. Mô tả triệu chứng (không nói nguyên nhân) và yêu cầu Claude đặt câu hỏi để thu hẹp vấn đề trước khi đưa giải pháp. Đánh giá: Claude có tìm ra đúng nguyên nhân không?
Bài 2.4 — Thiết kế hệ thống. Yêu cầu Claude đóng vai kiến trúc sư phản biện: bạn đưa ra thiết kế cho một tính năng (ví dụ hệ thống thông báo realtime), Claude chỉ ra điểm yếu, trade-off, và phương án thay thế. Xuất kết quả thành ADR (Architecture Decision Record).

🎯 Đề án Session 2: Refactor module legacy chỉ bằng chat

Chọn một module “khó chịu” (code cũ, hàm dài, không test) khoảng 300–1000 dòng.

  1. Dùng Claude viết characterization test (test ghi lại hành vi hiện tại) trước khi sửa gì.
  2. Yêu cầu Claude đề xuất kế hoạch refactor theo từng bước nhỏ, mỗi bước giữ test xanh.
  3. Thực hiện từng bước: copy code vào chat, nhận code mới, chạy test, phản hồi lỗi cho Claude.
  4. Cuối cùng nhờ Claude viết tài liệu cho module mới + mô tả PR.

Hoàn thành khi: toàn bộ test cũ vẫn xanh, độ phức tạp giảm rõ rệt (hàm ngắn hơn, đặt tên rõ hơn), và bạn ghi lại được những prompt nào giúp nhiều nhất. Bạn sẽ thấy việc copy/paste qua lại rất mệt, đó chính là lý do của Session 3.

Session 3 — Claude Code cơ bản

Thời lượng: ~4 giờ · Công cụ: Claude Code (terminal, extension VS Code/JetBrains, desktop, web)

Mục tiêu: để Claude làm việc trực tiếp trong codebase: đọc file, sửa code, chạy lệnh, chạy test, commit.

Kiến thức cần nắm:

npm install -g @anthropic-ai/claude-code   # hoặc theo hướng dẫn cài đặt chính thức
cd my-project
claude                                       # mở phiên tương tác
  • /init tạo file CLAUDE.md: “bộ nhớ” của dự án (cách build, test, convention). Claude đọc file này mỗi phiên.
  • Tham chiếu file bằng @duong/dan/file; dán ảnh chụp màn hình vào terminal.
  • Plan mode (Shift+Tab): Claude chỉ đọc và lập kế hoạch, chưa sửa gì. Dùng cho việc lớn.
  • Chế độ quyền: hỏi trước mỗi lần sửa, tự động chấp nhận chỉnh sửa, auto mode… Hiểu rủi ro của từng chế độ.
  • Esc để dừng, Esc Esc / /rewind để quay về checkpoint; /clear làm sạch context, /compact nén context.
  • Các lệnh hay dùng: /help, /model, /cost hoặc /usage, /config, /memory.
  • Quy trình chuẩn: Khám phá → Lập kế hoạch → Code → Kiểm thử → Commit. Cho Claude một cách tự kiểm tra (test, linter, chạy app) thì chất lượng tăng vọt.
Bài 3.1 — Hỏi đáp codebase. Mở Claude Code trong một repo open-source vừa clone (ví dụ một framework web nhỏ). Hỏi: “Request đi qua những lớp nào từ lúc vào đến lúc trả response?”, “Muốn thêm middleware thì sửa ở đâu?”. Kiểm chứng bằng cách tự đọc code.
Bài 3.2 — CLAUDE.md. Chạy /init trên dự án của bạn, đọc kỹ file sinh ra, sửa lại cho đúng và bổ sung: lệnh test, quy ước đặt tên, những thứ không được làm. Thử một yêu cầu trước và sau khi sửa CLAUDE.md để thấy khác biệt.
Bài 3.3 — Sửa bug bằng TDD. Chọn một issue/bug thật. Yêu cầu Claude: viết test tái hiện lỗi trước (phải fail), rồi mới sửa code cho test pass, rồi chạy toàn bộ test suite.
Bài 3.4 — Plan mode + rewind. Dùng plan mode cho một tính năng vừa phải. Chỉnh kế hoạch ít nhất 2 lần trước khi duyệt. Sau đó cố ý để Claude đi sai hướng, dùng rewind quay lại và đưa chỉ dẫn tốt hơn.
Bài 3.5 — Git workflow. Nhờ Claude tạo branch, commit với message chuẩn Conventional Commits, giải quyết một merge conflict có chủ đích, và viết mô tả PR.

🎯 Đề án Session 3: CLI app hoàn chỉnh từ con số 0

Dùng Claude Code xây một công cụ dòng lệnh quản lý chi tiêu cá nhân (hoặc chủ đề tương đương bạn thích), ngôn ngữ tuỳ chọn.

  • Lệnh: add, list (lọc theo ngày/danh mục), report (tổng theo tháng), import từ CSV, export JSON.
  • Lưu trữ bằng SQLite, có migration.
  • Test coverage ≥ 80%, linter/formatter được cấu hình, README đầy đủ.
  • Bắt đầu bằng plan mode; CLAUDE.md được cập nhật dần trong quá trình làm.
  • Lịch sử git sạch: mỗi tính năng một commit/PR có ý nghĩa.

Hoàn thành khi: người khác clone repo, làm theo README là chạy được, test xanh. Ghi lại: bạn tự gõ bao nhiêu % code? Lúc nào Claude làm sai và bạn đã sửa hướng bằng cách nào?

Session 4 — Claude Code nâng cao: tuỳ biến & tự động hoá

Thời lượng: ~4 giờ · Công cụ: Claude Code, GitHub

Mục tiêu: biến Claude Code thành công cụ riêng của nhóm bạn: lệnh tắt, quy trình chuẩn hoá, kiểm soát an toàn, chạy trong CI.

Kiến thức cần nắm:

  • Custom slash commands & Skills: đóng gói quy trình lặp lại (thư mục .claude/commands/, .claude/skills/<tên>/SKILL.md).
  • Hooks: chạy script tự động tại các thời điểm như trước/sau khi dùng tool (ví dụ tự format sau mỗi lần sửa file, chặn lệnh nguy hiểm). Cấu hình trong .claude/settings.json.
  • Permissions: allow/deny cho từng lệnh trong settings.json; phân biệt settings của user, project, local.
  • Subagents (.claude/agents/): agent chuyên biệt với context riêng (reviewer, test-writer, security auditor…).
  • Headless mode: claude -p "..." để dùng trong script, pipe dữ liệu, xuất JSON.
  • Git worktrees: chạy nhiều phiên Claude song song trên nhiều nhánh.
  • Claude Code trên web/cloud và GitHub Actions: giao việc qua issue/PR với @claude, review PR tự động.
  • Các lệnh có sẵn hữu ích: /review, /security-review, plugins & marketplace.
Bài 4.1 — Slash command đầu tiên. Tạo lệnh /fix-issue <số issue>: đọc issue, tìm code liên quan, viết test, sửa, chạy test, commit. Dùng nó cho 2 issue thật.
Bài 4.2 — Hooks. Viết 2 hook: (a) sau mỗi lần Claude sửa file thì chạy formatter/linter; (b) chặn mọi lệnh có rm -rf hoặc ghi vào file .env. Kiểm tra hook bằng cách cố ý yêu cầu Claude làm việc bị chặn.
Bài 4.3 — Subagent reviewer. Tạo subagent code-reviewer chỉ có quyền đọc, có checklist theo chuẩn nhóm. Sau mỗi tính năng, yêu cầu Claude gọi subagent này review.
Bài 4.4 — Headless trong script. Viết script shell dùng claude -p để: đọc git diff của ngày hôm nay và sinh changelog dạng Markdown. Gắn vào git hook hoặc cron.
Bài 4.5 — Làm song song. Tạo 2 worktree, chạy 2 phiên Claude cùng lúc: một phiên làm tính năng, một phiên viết thêm test. Gộp kết quả lại.

🎯 Đề án Session 4: Repo “AI-ready”

Nâng cấp repo từ đề án Session 3 (hoặc repo thật của nhóm) thành một repo mà cả nhóm dùng Claude hiệu quả và an toàn:

  1. CLAUDE.md hoàn chỉnh + .claude/settings.json với danh sách permission hợp lý (commit vào repo).
  2. Ít nhất 3 slash command/skill: /fix-issue, /new-feature (plan → code → test → PR), /release (cập nhật version, changelog, tag).
  3. Hooks: format tự động, chặn thao tác nguy hiểm, chạy test liên quan khi Claude kết thúc lượt.
  4. 2 subagent: code-reviewer và test-writer.
  5. GitHub Action dùng Claude: tự review mỗi PR và phản hồi khi được nhắc @claude trong issue.
  6. Tài liệu docs/ai-workflow.md hướng dẫn đồng nghiệp dùng các công cụ trên.

Hoàn thành khi: tạo một issue mới, gõ @claude, nhận được PR kèm test và được review tự động, còn bạn chỉ cần đọc và merge.

Session 5 — MCP: kết nối Claude với thế giới bên ngoài

Thời lượng: ~4 giờ · Công cụ: Claude Code, Claude Desktop, MCP SDK (Python hoặc TypeScript)

Mục tiêu: hiểu Model Context Protocol, dùng MCP server có sẵn, và tự viết server cho hệ thống của mình.

Kiến thức cần nắm:

  • MCP là chuẩn mở để Claude dùng tools (hành động), resources (dữ liệu) và prompts (mẫu) từ server bên ngoài.
  • Transport: stdio (chạy local) và HTTP (server từ xa, có xác thực OAuth).
  • Thêm server vào Claude Code: claude mcp add <tên> -- <lệnh>, xem bằng /mcp; scope project (file .mcp.json) và scope user.
  • Connectors trên claude.ai / Claude Desktop.
  • Bảo mật: chỉ dùng server tin cậy, cấp quyền tối thiểu, cẩn thận prompt injection từ dữ liệu bên ngoài.
  • Công cụ debug: MCP Inspector.
Bài 5.1 — Dùng server có sẵn. Gắn 3 MCP server vào Claude Code: GitHub, một server database (Postgres/SQLite), và Playwright (điều khiển trình duyệt). Yêu cầu Claude: “Tìm 5 issue mở lâu nhất, đọc code liên quan, đề xuất cách sửa”.
Bài 5.2 — Kiểm thử giao diện bằng trình duyệt. Với Playwright MCP, yêu cầu Claude mở web app của bạn, thực hiện luồng đăng ký/đăng nhập, chụp màn hình, báo lỗi giao diện, rồi tự sửa code.
Bài 5.3 — Hello MCP. Viết MCP server tối giản (ví dụ Python dùng FastMCP) với 1 tool get_weather(city) trả dữ liệu giả. Test bằng MCP Inspector, rồi gắn vào Claude Code.
Bài 5.4 — Resources & prompts. Mở rộng server: thêm resource trả về nội dung file cấu hình, và một prompt mẫu “phân tích log”.

🎯 Đề án Session 5: MCP server cho hệ thống của bạn

Xây MCP server cho một hệ thống thực tế, ví dụ DB của CLI chi tiêu (Session 3), hệ thống ticket nội bộ, hoặc API công ty.

  • Ít nhất 5 tool, trong đó có tool chỉ đọc và tool ghi (tool ghi phải có xác nhận/kiểm tra đầu vào chặt chẽ).
  • Ít nhất 2 resource và 1 prompt.
  • Xử lý lỗi rõ ràng, mô tả tool viết tốt để Claude biết khi nào dùng tool nào.
  • Hỗ trợ cả stdio và HTTP; có test tự động cho các tool.
  • Đóng gói để đồng nghiệp cài được bằng một lệnh; khai báo trong .mcp.json của repo.

Hoàn thành khi: từ Claude Desktop hoặc Claude Code, bạn hỏi bằng ngôn ngữ tự nhiên (“Tháng này tôi tiêu cho ăn uống nhiều hơn tháng trước bao nhiêu? Thêm khoản 50k cà phê hôm nay”) và Claude tự gọi đúng tool để trả lời và cập nhật dữ liệu.

Session 6 — Lập trình với Claude API

Thời lượng: ~4 giờ · Công cụ: Anthropic SDK (Python/TypeScript), Claude Console

Mục tiêu: tích hợp Claude vào sản phẩm của bạn qua API.

Kiến thức cần nắm:

pip install anthropic          # hoặc: npm install @anthropic-ai/sdk
export ANTHROPIC_API_KEY=...

from anthropic import Anthropic
client = Anthropic()
msg = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=1024,
    system="Bạn là trợ lý kỹ thuật, trả lời ngắn gọn bằng tiếng Việt.",
    messages=[{"role": "user", "content": "Giải thích CAP theorem"}],
)
print(msg.content[0].text)
  • Messages API: system, messages (hội thoại nhiều lượt do bạn tự lưu), max_tokens, temperature, stop_reason.
  • Streaming để hiển thị câu trả lời dần dần.
  • Tool use (function calling): khai báo tool bằng JSON Schema, xử lý tool_use → trả tool_result.
  • Structured output: ép đầu ra đúng schema JSON.
  • Vision & PDF: gửi ảnh, tài liệu.
  • Prompt caching (giảm chi phí và độ trễ cho phần prompt lặp lại), Message Batches (xử lý hàng loạt, rẻ hơn), đếm token.
  • Xử lý lỗi: rate limit, retry, timeout; theo dõi chi phí trên Console. Không bao giờ commit API key.
  • Workbench trong Console để thử prompt trước khi code.
Bài 6.1 — CLI chat. Viết chương trình chat trong terminal có streaming, lưu lịch sử hội thoại, lệnh /reset, in số token và chi phí ước tính sau mỗi lượt.
Bài 6.2 — Trích xuất dữ liệu có cấu trúc. Đưa vào 20 email/hoá đơn (ảnh hoặc PDF), trích xuất thành JSON theo schema (người gửi, số tiền, ngày, hạng mục). Viết script kiểm tra độ chính xác so với đáp án tự gán nhãn.
Bài 6.3 — Tool use. Cho Claude 3 tool: get_exchange_rate, calculator, search_products (dữ liệu giả). Tự viết vòng lặp xử lý tool call cho câu hỏi “Laptop rẻ nhất dưới 1000 USD là bao nhiêu tiền Việt?”.
Bài 6.4 — Tối ưu chi phí. Với một system prompt dài (~10k token), đo chi phí và độ trễ khi gọi 10 lần có và không có prompt caching. Sau đó chạy 100 yêu cầu bằng Batches API và so sánh giá.

🎯 Đề án Session 6: Chatbot hỏi đáp tài liệu nội bộ (RAG)

Xây ứng dụng web cho phép hỏi đáp trên bộ tài liệu của bạn (tài liệu dự án, wiki công ty, hoặc tài liệu của một thư viện open-source).

  • Pipeline nạp dữ liệu: chia nhỏ tài liệu, tạo embedding, lưu vào vector DB (pgvector, Chroma… tuỳ chọn); kết hợp tìm theo từ khoá.
  • Trả lời có trích dẫn nguồn; nói “không biết” khi tài liệu không có thông tin.
  • Tool use: Claude được phép gọi thêm tool search_docs nhiều lần, và một tool nghiệp vụ (ví dụ tạo ticket khi không trả lời được).
  • Web UI có streaming (FastAPI/Express + frontend tuỳ ý; có thể dùng chính Claude Code để xây).
  • Prompt caching cho system prompt; log token và chi phí cho mỗi câu hỏi.
  • Bộ 30 câu hỏi kiểm thử kèm đáp án mong đợi, script chấm điểm tự động.

Hoàn thành khi: ≥ 85% câu hỏi kiểm thử trả lời đúng và có trích dẫn, chi phí trung bình mỗi câu hỏi được đo và ghi trong README.

Session 7 — Xây dựng Agent

Thời lượng: ~4 giờ · Công cụ: Claude API, Claude Agent SDK

Mục tiêu: hiểu agent hoạt động thế nào và tự xây agent đáng tin cậy cho công việc thực tế.

Kiến thức cần nắm:

  • Agentic loop: model → gọi tool → nhận kết quả → lặp lại cho đến khi xong. Phân biệt workflow (luồng cố định do code điều khiển) và agent (model tự quyết bước tiếp theo); chỉ dùng agent khi thật sự cần.
  • Các mẫu thiết kế: prompt chaining, routing, chạy song song, orchestrator–workers, evaluator–optimizer.
  • Claude Agent SDK: dùng lại “bộ máy” của Claude Code (công cụ đọc/sửa file, chạy lệnh, quản lý context, subagent, MCP) trong chương trình của bạn.
  • Quản lý context cho tác vụ dài: tóm tắt, ghi chú ra file, subagent.
  • Evals: bộ test cho agent, chấm bằng code hoặc dùng LLM làm giám khảo.
  • Guardrails: giới hạn số bước và chi phí, sandbox, cần người duyệt cho hành động nguy hiểm, chống prompt injection.
Bài 7.1 — Agent từ con số 0. Không dùng framework, tự viết agent ~100 dòng có 3 tool: read_file, list_dir, run_tests. Giao nhiệm vụ “tìm vì sao test X fail”. Ghi log mọi bước để hiểu vòng lặp.
Bài 7.2 — Agent SDK. Viết lại bài 7.1 bằng Claude Agent SDK, thêm MCP server từ Session 5. So sánh lượng code và khả năng.
Bài 7.3 — Multi-agent. Xây agent nghiên cứu: một orchestrator chia câu hỏi (ví dụ “so sánh 3 thư viện ORM cho Node.js”) thành các phần, giao cho subagent tìm hiểu song song, rồi tổng hợp thành báo cáo.
Bài 7.4 — Evals. Viết 15 test case cho agent bài 7.2, chấm điểm tự động. Thay đổi system prompt và đo xem điểm tăng hay giảm.

🎯 Đề án Session 7: Agent tự động review Pull Request

Xây agent nhận đường dẫn một PR trên GitHub và tạo bản review chất lượng như một senior.

  • Đọc diff, mở các file liên quan để hiểu ngữ cảnh (không chỉ nhìn diff).
  • Chạy test và linter trong sandbox (Docker), đưa kết quả vào nhận xét.
  • Dùng subagent chuyên biệt: correctness, security, performance; orchestrator gộp và loại bỏ nhận xét trùng lặp hoặc kém tin cậy.
  • Đăng nhận xét inline lên PR qua GitHub API (có chế độ --dry-run).
  • Giới hạn chi phí và số bước cho mỗi lần chạy; log đầy đủ để debug.
  • Bộ eval: 10 PR có bug được cài sẵn, đo tỉ lệ phát hiện và tỉ lệ báo sai.

Hoàn thành khi: agent phát hiện ≥ 7/10 bug cài sẵn, tỉ lệ nhận xét vô ích thấp, và chạy được trong GitHub Actions trên repo của bạn.

Session 8 — Đưa vào thực tế & tổng kết

Thời lượng: ~4 giờ + thời gian làm đồ án (1–2 tuần)

Mục tiêu: dùng Claude an toàn, tiết kiệm, đo được hiệu quả; tích hợp vào công việc hằng ngày của bạn và nhóm.

Kiến thức cần nắm:

  • Bảo mật: không đưa secret vào prompt, phòng prompt injection (dữ liệu từ web, email, issue là dữ liệu chứ không phải mệnh lệnh), nguyên tắc quyền tối thiểu cho tool, luôn review code AI sinh ra.
  • Chi phí: chọn model phù hợp từng bước (Haiku cho phân loại, Sonnet cho việc chính, Opus cho việc khó), caching, batch, giới hạn max_tokens.
  • Quan sát: log prompt/response, token, độ trễ, tỉ lệ lỗi; chạy eval định kỳ khi đổi prompt hoặc đổi model.
  • Hệ sinh thái: Claude trên desktop/mobile, Claude in Chrome, Claude trong Slack, tác vụ định kỳ (scheduled tasks), Claude Code trên web chạy trong cloud.
  • Làm việc nhóm: chia sẻ CLAUDE.md, skills, plugins, MCP config; quy ước review code do AI viết.
Bài 8.1 — Tấn công thử. Thử tấn công prompt injection vào chatbot Session 6 (ví dụ chèn chỉ thị độc vào tài liệu) và agent Session 7 (chèn chỉ thị vào mô tả PR). Ghi lại lỗ hổng và cách khắc phục.
Bài 8.2 — Tối ưu chi phí. Lấy chatbot Session 6, giảm chi phí mỗi câu hỏi ít nhất 40% mà điểm eval không giảm quá 3% (đổi model cho từng bước, caching, rút gọn context).
Bài 8.3 — Thói quen hằng ngày. Trong 1 tuần, ghi nhật ký: việc gì bạn giao cho Claude, mất bao lâu, kết quả thế nào. Cuối tuần tổng kết việc nào Claude làm tốt, việc nào nên tự làm.

🏆 Đồ án tốt nghiệp: Sản phẩm end-to-end có Claude làm lõi

Chọn một đề tài (hoặc tự đề xuất) giải quyết vấn đề thật của bạn hoặc công ty:

  • A. Trợ lý on-call: nhận cảnh báo (webhook), đọc log/metrics qua MCP, phân tích nguyên nhân gốc, đề xuất hoặc tạo PR sửa lỗi, báo cáo vào Slack.
  • B. Nền tảng tự động hoá tài liệu: theo dõi repo, tự cập nhật tài liệu API/kiến trúc khi code thay đổi, mở PR tài liệu, có hệ thống hỏi đáp trên tài liệu đó.
  • C. Công cụ migration: agent chuyển codebase từ công nghệ cũ sang mới (ví dụ JavaScript → TypeScript, Python 2 → 3, REST → GraphQL) theo từng module, có test chứng minh hành vi không đổi.
  • D. SaaS mini: ứng dụng có người dùng thật (ví dụ chấm bài code cho sinh viên, tóm tắt hợp đồng, sinh test case từ đặc tả).

Yêu cầu bắt buộc (áp dụng toàn bộ những gì đã học):

  1. Toàn bộ dự án được phát triển bằng Claude Code với repo “AI-ready” (CLAUDE.md, skills, hooks, subagents, CI có Claude review).
  2. Dùng Claude API hoặc Agent SDK làm lõi xử lý, có tool use.
  3. Có ít nhất một MCP server tự viết.
  4. Có bộ eval tự động chạy trong CI.
  5. Có guardrails: giới hạn chi phí, xác nhận hành động nguy hiểm, phòng prompt injection.
  6. Có dashboard hoặc log theo dõi token, chi phí, độ trễ.
  7. Tài liệu: README, sơ đồ kiến trúc, báo cáo chi phí, bài viết tổng kết bài học (có thể đăng lên chính blog này).

Hoàn thành khi: sản phẩm được deploy, có ít nhất một người khác dùng thật, và bạn trình bày demo 10 phút giải thích kiến trúc, quyết định thiết kế, chi phí, cũng như những gì Claude làm tốt và chưa tốt.

Mẹo xuyên suốt lộ trình

  • Luôn kiểm chứng. Claude rất giỏi nhưng vẫn có thể sai. Hãy dựa vào test, linter, và chạy code thật.
  • Ngữ cảnh là tất cả. Phần lớn câu trả lời kém đến từ thiếu ngữ cảnh, không phải do model yếu.
  • Cho Claude cách tự kiểm tra (test, ảnh chụp mong muốn, lệnh build): chất lượng tăng rõ rệt.
  • Lặp nhanh, sửa hướng sớm. Thấy đi sai thì dừng (Esc), rewind, đưa chỉ dẫn rõ hơn.
  • Hỏi Claude về chính Claude: trong Claude Code, cứ hỏi “làm sao để cấu hình hook…”, Claude sẽ tra tài liệu và hướng dẫn.
  • Ghi chép: sau mỗi session viết vài dòng “học được gì / prompt nào hiệu quả” vào blog này.
